# 定时任务与自动化执行

> 本文说明支撑 `docs/ROADMAP.md` 的**唯一**定时任务：它每次做什么、按什么分流、边界在哪、怎么停。
> 目的是让开发在无人值守下可控推进，而不是让机器随意改代码。

## 一、只有一个任务

| 任务 | 频率 | 说明 |
|---|---|---|
| **NT-Dpet 开发与守护** | **每小时 :00** | 抢锁 → 备份 → 按时段分流到「回归 / 文档同步 / 开发推进」三选一 |

原先是四个任务（开发推进整点、开发推进半点、每日回归、每周文档同步），2026-10-23 合并为一个。合并的理由是：它们共用同一把并发锁、同一份备份、同一个仓库，拆成多个只会让抢锁互相干扰，且调度时间无法协同。

### 1.1 按时段分流

单任务要承担三种职责，靠本机时间判定，不依赖额外状态文件：

| 触发时刻 | 执行内容 | 是否改业务代码 |
|---|---|---|
| 08:00 | **回归检查**：构建、五包单测、界面冒烟、仓库一致性、声明一致性、进度统计 | 否（仅可写阻塞项表） |
| 周一 09:00 | **文档同步**：完成率、README 对齐代码、CHANGELOG 开发进展、声明补齐 | 否 |
| 其余整点 | **开发推进**：做 ROADMAP 中第一个未勾选任务 | 是（仅该任务范围） |

这样每周有 7 次回归、1 次文档同步，其余时刻都用于开发推进。分流是确定性的：同一时刻永远做同一类事，不受上一轮结果影响。

### 1.2 清单规模

M0–M8 共 **71 个可勾选项**，对应 **75 个任务编号**（M7 一行并列了 5 个通道安装项，合并为一个可勾选项）。M0 为 22 项，每项含前置、改动位置、做法、验收。

## 二、执行边界（硬约束）

提示词层面固定，任何一条都不因「效率」而放宽：

1. **一次一项**：只做 ROADMAP 中第一个未勾选任务，不并行、不跳跃。
2. **不通过不提交**：构建或测试失败即回退，任务转入「阻塞项登记」，不留下半成品提交。
3. **不越目录**：不写 `~/.dsh`、`~/.agents`，不修改项目目录之外的任何文件。
4. **不删除文件**：自动化任务不具备删除权限；清理类操作一律留待人工确认。
5. **不改版本**：里程碑中途不升版本号，仅收口任务负责升版与打 tag。
6. **声明同步**：引入新依赖时，`NOTICE`、`docs/CREDITS.md`、`docs/ADOPTION-REGISTER.md` 必须在同一次提交内更新；未声明许可的项目不得引入。
7. **不使用 `--no-verify`，不 force push，不使用 `--amend`。**

## 二之一、并发保护

单次任务耗时不确定，可能超过一小时而撞上下一轮。任务启动时先 `mkdir /tmp/nt-dpet-dev.lock`：

- 成功：正常执行，结束前 `rmdir` 释放
- 失败：判定上一轮仍在跑，本次直接跳过并输出说明
- 锁目录超过 **75 分钟**：视为陈旧锁（上次异常退出），删除后继续

该机制牺牲少量执行机会，换取「任何时刻只有一个进程在改仓库」，避免提交互相覆盖。

## 二之二、备份

每次运行（不论分流到哪一类）第一步执行 `./scripts/backup.sh`，产物落 `/Volumes/Expand/Backups/nt-dpet`：

| 产物 | 内容 |
|---|---|
| `nt-dpet-<时间戳>.bundle` | 全部提交历史，可用 `git clone` 恢复 |
| `nt-dpet-<时间戳>-worktree.tar.gz` | 工作树快照，含未提交改动，排除 node_modules / dist / .git / runtime |
| `manifest-<时间戳>.txt` | 时间、分支、提交号、文件数 |

卷未挂载时脚本告警并返回 0（不阻塞开发）；脚本本身不删除任何备份，清理由人工执行。

## 三、推送通道

`github.com` 的 HTTPS 在本机被网络阻断，`git push` 走 SSH：

```
origin  ssh://git@ssh.github.com:443/ntars/NT-Dpet.git
core.sshCommand  ssh -p 443
```

远端信息读取只用 `api.github.com`（该域名可达），推送失败时重试三次并保留本地提交。

## 四、如何暂停与恢复

- 只有一个任务：在 WorkBuddy 的定时任务列表中把它改为暂停即可，已勾选的任务不会回退。
- 恢复前若中间有人工改动，先手动跑一次回归（构建 + 五包单测 + 冒烟），确认干净再恢复。
- 若想临时提高频率，不要新建第二个任务——两个任务共用同一把锁，会互相跳过；改 rrule 即可。

## 五、人工介入点

以下事项自动化任务**不会**自行决定，需人工确认：

| 事项 | 原因 |
|---|---|
| 引入新第三方依赖 | 涉及许可判断，须登记三处声明 |
| Live2D Cubism Core、NapCat 等禁止分发项 | 只能引导用户自装，不能进安装包 |
| 版本号与 tag | 里程碑收口需人工确认可交付性 |
| 涉及删除、迁移、权限变更的操作 | 不可逆，按项目规则需先列清单再确认 |
| 对外发布（安装包、官网下载入口） | 涉及对外承诺，须人工核验后发布 |
| **暂停或删除本任务** | 自动化不能自己停自己，这是权限边界 |

## 六、验收基线

开发推进完成，必须同时满足：

```bash
npx pnpm@9 -r --filter './packages/**' build      # 32 包全过
npx pnpm@9 --filter '@nt-dpet/<包>' run test      # 受影响包全过
node packages/ui/web/test/smoke.mjs               # 改动界面时必跑
```

回归检查额外校验：远端与本地文件树逐文件哈希一致，三项差异（内容不一致 / 远端残留 / 漏推）均为 0。

## 七、何时算「没有事情做」

ROADMAP 全部勾选且阻塞项为空时，任务不会虚构新工作：它会转为只跑回归，并在结论中明确写出「清单已全部完成，建议暂停本任务」。**这句话出现后需要人工暂停**——自动化无权停掉自己。
