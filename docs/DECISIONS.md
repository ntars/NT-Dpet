## A. 产品形态（1-6）

| # | 决策 | 依据 |
|---|---|---|
| 1 | NT-Dpet 是 DeepSeek Harness 的**发行版**，不是独立框架 | 主人：「以 DeepSeek harness 为壳，各功能以插件形式加进去」 |
| 2 | **全 TypeScript**，Python 仅在本地声音服务中作为可选子进程存在 | 主人：「python 如果觉得累赘就不用了，以 DSH 官方壳为准」 |
| 3 | 许可 **AGPL-3.0** | 主人早期明确选择 |
| 4 | 做**自有市场**，与官方 Discover、dsh-market 并存 | 主人：「和官方的还有 dsh-market 不一样，我们有自己的市场和插件目录」 |
| 5 | 市场形态是**整装组合包**（一组插件 + 一份配置 + 一套人格），不是零件货架 | 主人在「市场定位」四项中选「整装组合包」 |
| 6 | 组合包**全部免费**；官方预设由主人维护，同时支持社区提交 | 主人选「全部免费」＋「内置预设我这个开发者来，但支持社区」 |

## B. 交付与部署（7-12）

| # | 决策 | 依据 |
|---|---|---|
| 7 | 做**独立安装器**，双击即用 | 主人在「不做安装器」后明确改口：「那就做安装器」 |
| 8 | 外壳用 **Electron**，安装器与桌宠共用一份 | 主人选「Electron（壳共用）」 |
| 9 | 三端并行，打包顺序 **Windows → macOS → Linux** | 主人选「Win → Mac → Linux」 |
| 10 | 下载源**国内镜像优先**，失败回退官方源 | 主人选「国内镜像优先」 |
| 11 | 安装器**锁定 DSH 具体版本**并校验，不装 `latest` | 技术事实：`latest` dist-tag 曾指向不可用的 `0.0.1-rc.x`，可用版本在 `next` tag |
| 12 | 安装器写入默认视图为「对话」，不是「代码日志」 | 主人：「dsh 中间的对话区默认就是代码日志，左侧可切换为对话窗口」 |

## C. 架构（13-16）

| # | 决策 | 依据 |
|---|---|---|
| 13 | 日常对话**不走 DSH 的 agent loop**，走自建轻量通道 | 主人选「不走，但用户可以通过 dsh 的工作窗口看详细日志」 |
| 14 | 需要动手时才唤起 DSH 工具链（adb / 浏览器 / Minecraft） | 同上，行动能力借 DSH 工具系统 |
| 15 | 插件拆 **29 个独立包**，界面上按 **7 个组**展示 | 主人选「29 个包，界面上分 7 组」 |
| 16 | 隔离分三级：L1 逻辑隔离 / L2 错误边界 / L3 进程隔离 | 技术事实：Cordis 插件共享同一 Node 进程，「互不影响」有物理上限 |
