## A. 产品形态（1-6）

| # | 决策 | 依据 |
|---|---|---|
| 1 | NT-Dpet 是 DeepSeek Harness 的**发行版**，不是独立框架 | 主人：「以 DeepSeek harness 为壳，各功能以插件形式加进去」 |
| 2 | **全 TypeScript**，Python 仅在本地声音服务中作为可选子进程存在 | 主人：「python 如果觉得累赘就不用了，以 DSH 官方壳为准」 |

| 6 | 组合包**全部免费**；官方预设由主人维护，同时支持社区提交 | 主人选「全部免费」＋「内置预设我这个开发者来，但支持社区」 |

| S3 | **`@nt-dpet/proactive` 吸收 bili-whale 的四条机制**：窗口内随机时刻醒、拒绝权（一定概率今天不主动）、双视角日记、沉默衰减 | 现有设计只有「唤醒 10% 随机开口」，缺「何时醒」「可否不醒」「不被回应怎么办」三层 | `packages/proactive/`、`packages/memory/` |
| S4 | **用户资产与宿主数据分离**：人格 / 凭据 / 日记 / 账本 / 还原点放 `…/NT-Dpet/user/`，**不放进 `dsh-home/`** | `dsh-home` 里是宿主自己的 profile、cache、会话，重建 profile 时可能被整体清掉；日记和亲密度被清掉等于宠物死了一次。两者同在 `NT-Dpet` 根下，但仍属不同目录（§2.3 已定的布局，此处只补「用户资产单独一层」） | 全包统一路径常量，落 `packages/privacy/` 或单独 `paths` 模块 |
| S5 | **对手发言一律走草稿送审**，主人本人可直发 | bili-whale 的双侧回复设计；比我们 `privacy` 包现有描述更可执行 | `packages/privacy/` |

`yangyu-bot` **查无此项目**（§5.7.4），在主人补链接前不为它做任何设计假设。
