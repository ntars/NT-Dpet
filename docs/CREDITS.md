> 核实日期：2026-10-22　｜　所有许可信息均来自各项目仓库的 `LICENSE` 文件或官方许可页
> 本文档只记录**实际使用**或**实际借鉴**的项目。看到名字不代表它是我们的代码。

NT-Dpet 本身没有发明多少东西。人格结构、消息协议、语音合成、游戏接入、桌宠渲染，几乎每一层都站在别人的肩膀上。这份文档把所有借来的东西列清楚，包括**法律边界在哪、为什么会卡在那里**。

如果你发现某个项目被漏掉了，或者某条许可信息写错了，请开一个 issue——这类错误会直接变成法律风险，我们宁可被指出。

## 一、关于「用」的三种方式

同一份列表里混着三种完全不同的关系，混为一谈会出问题，所以先分清：

| 方式 | 含义 | 许可影响 |
|---|---|---|
| **直接依赖** | 代码被打进我们的产物，随安装包一起分发 | 必须许可兼容，必须保留版权声明 |
| **运行时调用** | 用户机器上独立运行的进程，我们只发请求 | 不构成衍生作品，但**不得随包分发** |
| **参考实现** | 读过它的设计与源码，自己重写 | 不复制代码即无义务，但应当致谢 |

下文每个项目都会标明属于哪一类。

## 四、运行时调用（独立进程，不随包分发）

这一类最需要小心。它们都是**用户机器上单独安装的软件**，我们只通过 HTTP、CLI 或 IPC 调用。

| 项目 | 许可 | 用途 | 为什么不能内置 |
|---|---|---|---|
| **NapCatQQ** | **自定义许可**（见 §六.1） | QQ 个人号协议端，OneBot 11 实现 | 禁止商用、禁止公开发布修改版，与 AGPL 直接冲突 |
| **GPT-SoVITS** | MIT | 本地语音合成（同音色说话、念白） | 许可允许，但依赖 CUDA 与数 GB 权重，不适合进安装包。且它是 Python，只能独立进程 |
| **RVC**（Retrieval-based Voice Conversion） | MIT | 歌声转换（SVC）首选，素材门槛低 | 同上：Python + GPU + 模型权重 |
| **so-vits-svc** | **AGPL-3.0** | 歌声转换备选，颤音与假声更好 | 同上。许可本身与我们兼容 |

## 六、许可边界：四条必须写下来的红线

这三条不是「注意事项」，是**做错了会真的出事**的地方。

### 6.1 NapCat：不是开源许可，是「有限再分发许可」

它的 `LICENSE` 原文标题是 *Limited Redistribution License for NapCat*，关键条款四条：

1. 未经作者明确许可，**禁止使用、复制、修改、分发**
2. 允许再分发，但必须附带完整许可文本并标注来源与版权
3. 允许为再分发做小幅修改，但**修改后的代码不得公开发布**
4. **不得用于任何商业目的**

第 3、4 条与 AGPL-3.0 的「必须公开源码」「不得附加限制」正面冲突。所以：

- ❌ 不把 NapCat 代码放进仓库
- ❌ 不把 NapCat 打进安装包
- ❌ 不 fork、不修改
- ✅ 只做**用户自行安装 → 我们连它的 HTTP/WebSocket 接口**
- ✅ 在文档和界面里明确标注这是第三方软件

同样要小心的还有 2025 年 9 月那次事故的教训：NapCat WebUI 默认监听 `0.0.0.0` 且固定 token，被扫描后操纵发违法信息，**波及账号与群全部永久封禁**。我们的连接器必须默认只听 `127.0.0.1`。

### 6.2 Live2D Cubism Core：专有软件，不能进仓库

`live2dcubismcore.min.js` 不属于任何开源许可，是 Live2D Inc. 的专有软件。官方许可页写明：

- 免费下载，但受 *Live2D Proprietary Software License Agreement* 约束
- 发布需要 Publication License；**个人与小规模企业豁免**
- 但「应用作为主要业务元素且年销售额超过 **2000 万日元**」时，必须签约并付费

所以：

- ❌ 不把 Cubism Core 放进仓库或安装包
- ✅ 首次使用时弹协议，由用户确认后**从官网下载**到本地
- ✅ 同时提供**不依赖 Live2D 的降级路径**（序列帧立绘），让不想走这一步的用户也能用

### 6.3 ADBKeyboard：GPL-2.0，与 AGPL-3.0 不兼容

FSF 的立场很明确：GPLv2（不带「或更高版本」）与 GPLv3/AGPLv3 不兼容。ADBKeyboard 声明的正是 GPL-2.0。

作为独立 APK 通过广播调用，属于「聚合」而非「衍生」，可以用。但**一旦打进安装包分发**，就触发 GPL-2.0 的分发义务，且与我们的许可冲突。

结论：只引导用户自行安装，安装包里不放。

### 6.4 wxauto 与微信 UI 自动化：连「参考」都算不上

**wxauto**（`cluic/wxauto`，约 7.4k star）的 README 原文写着：

> 代码仅用于对 UIAutomation 技术的交流学习使用，**禁止用于实际生产项目**，请勿用于非法用途和商业用途。

作者自己把生产使用划掉了。它只在 Windows 上跑（基于 UIAutomation），本项目面向 macOS，**技术上根本用不上**，所以它不在这份文档的任何依赖清单里。

macOS 的等价物（`wxauto-mac`、`wxauto-mcp-macos` 等）走的是 AppleScript + Accessibility API，原理等价于「替人点鼠标」：发送靠剪贴板粘贴 + 回车，读取靠全选复制。这条路我们**不做默认项**；若将来保留，只做「只发不收」的可选桥，默认关闭，并在申请「辅助功能」权限前明示它拿到的是整机 UI 控制权。

### 7.5 主动性与克制

| 项目 | 许可 | 借鉴了什么 |
|---|---|---|
| **dsh-bili-whale**（`Alterssss/dsh-bili-whale`） | MIT | 见下。它刷 B 站的功能我们不需要，**它怎么劝自己少说话才是要学的** |

具体借了四条，都已写进 `TECH-RESEARCH.md` §5.7.3：

1. **窗口内随机时刻醒**，不是整点触发。
2. **拒绝权**：一定概率今天就是不主动。宠物得有不想说话的自由，否则只是定时器。
3. **双视角日记**：写给主人的那本有细节有情绪，写给自己的那本不加滤镜。
4. **沉默衰减**：连着几天没被回应，分享额度逐渐降到零，但日记照写。这是情感逻辑，不是限流逻辑。

另外借了它的**人设文件五段式结构**（`# 我是谁` / `# 说话` / `# 我在意什么` / `# 我绝不会` / `# 日记怎么写`，前 3000 字有效），用于撰写本项目四套 L1 人格锚点。

这个项目明确**不内置任何人格**，默认是个不撒娇、不叫「主人」的中性助手——这一点与我们的「人格包外置」互相印证。

## 九、我们的承诺

1. **不修改上游**。不改 DSH、不 fork 任何第三方项目。所有改动发生在插件层与配置补丁层。
