## 一、她是什么样的

NT-Dpet 不是一个聊天窗口加一层皮肤。它把「她」拆成可以分别维护的部件：情绪、记忆、主动性、表达、形象。每个部件都可以单独替换，也都可以关掉——关掉之后不是白屏，是退回到更简单的形态。

### 1.1 四种关系，四套性格

初始时选择一种关系定位。**这不是「同一个角色调整亲密度」，而是四套不同的性格内核**：

| 关系 | 默认称呼你 | 说明 |
|---|---|---|
| 妹妹 | 哥哥 | 会主动索取关注，闹完小脾气会自己回来 |
| 伴侣 | 宝宝 / 乖乖 / 老公 | 「亲爱的」过于正式，不进入默认值 |
| 朋友 | 你的名字或外号 | 平等相处，不多黏 |
| 助手 | 老板 | 敬称，保持距离感 |

称呼是**默认值联动，不是硬绑定**：选了伴侣也可以改叫别的，人格文本只读取最终值。另有猫娘浓度三档（清淡 / 标准 / 浓），与称呼互不影响。

> 状态：人格包结构已定，四份内核文本尚未撰写（`content` 为空）。

### 1.2 她会难过，也会自己好起来

情绪分五维，两类归属：

| 维度 | 归属 | 含义 | 初始值 |
|---|---|---|---|
| `mood` | 实例全局 | 此刻心情 | 0.5 |
| `energy` | 实例全局 | 此刻精力 | 0.7 |
| `affection` | 按人 | 对某人的好感 | 0.1 |
| `trust` | 按人 | 对某人的信任（慢涨快跌） | 0.1 |
| `intimacy` | 按人 | 与某人的亲密 | 0.0 |
| `familiarity` | 按人 | 熟悉度，决定注入多少画像 | 0.0 |

初始值是「略有好感」——不冷淡，也不自来熟，感情从零开始累积。换人格时五维**全部保留**：人格是皮肤，不是另一个角色。

### 1.3 她记得事情，但不会把什么都倒出来

记忆分两层：

| 层 | 存什么 | 写入时机 |
|---|---|---|
| 原文层 | 对她说的话 + 她的回复，逐条原样 | 每轮对话，同步写 |
| 事实层 | 提炼后的一句话事实 | 每轮结束后 5 秒内异步提炼 |

**异步是硬要求**：同步提炼会让每句话多一次模型调用，延迟翻倍。正确顺序是先回用户，再慢慢消化。

记忆有衰减，四档预设：不衰减 / 缓慢（半衰期 30 天）/ 标准（7 天，默认）/ 快速（2 天）。即使选「不衰减」，也不会什么都注入——而是走三层裁决（语义 0.4 / 时间 0.4 / 重要度 0.2 加权），避免「去年的喜欢」和「今天的讨厌」同时出现在上下文里。

> 状态：`@nt-dpet/memory` 为骨架，尚未实现。当前对话不跨轮保留上下文。

### 1.4 她不会一直说话

主动开口要过三道闸门，顺序固定：

| 闸门 | 回答的问题 | 判据 |
|---|---|---|
| 一、时机 | 现在该醒吗 | 作息窗口内 + 距上次主动 ≥ 冷却时长 + 拒绝权判定 |
| 二、话由 | 有值得说的吗 | 记忆里有未消化的事 / 情绪偏离基线 / 时间性事件 |
| 三、分寸 | 说了会不会打扰 | 今日额度 > 0 + 不在静默时段 + 用户不在忙碌中 |

四个不那么显然的选择：

- **随机时刻醒，不定整点**。整点会有机械感——「又到十点了，她该说话了」；随机时刻更像「她刚好想起你」
- **拒绝权**：即使三道闸门全过，仍有 30% 概率今天就是不主动。永远按规则开口的东西不叫性格，叫会说话的闹钟
- **沉默衰减**：连续 3 天没被回应，额度开始下降；第 7 天归零，不再主动分享，但**日记照写**。这不是限流（少打扰你），而是她察觉你没接话、慢慢把心事收回去。你哪天主动开口，额度立刻复位
- **双视角日记**：给主人的那本有细节有情绪，给自己的那本不加滤镜。有人看着的时候写不出真话；诚实的那本才是长期记忆的原料

> 状态：设计已定，`@nt-dpet/proactive` 为骨架。

## 三、值得说的设计

这一节讲「为什么这样做」，以及那些容易被忽略、但直接影响手感的选择。

### 3.1 情绪的回落用指数曲线，不用线性

```
v(t) = 基线 + (当前值 − 基线) × e^(−λt)
λ = ln2 / 半衰期
```

四档半衰期：1 小时 / 4 小时（默认）/ 12 小时 / 不回落。

选指数而非线性，是因为人的情绪「刚开始淡得快、越久越淡」；线性衰减会在某一刻突然归零，非常假。半衰期这一档跨度覆盖了「几小时到半天」的直觉区间。

**三个实现细节**：

- **惰性回归**：不靠定时器推进时间，而是每次读取时按「距上次更新过了多久」现算。好处是进程崩溃重启不需要补偿计算——不会因为挂了 3 小时，回来就算出一个离谱的值
- **阈值落盘**：关系跨过 0.25 / 0.50 / 0.75 任一档位立即落盘，其余情况每 60 秒批量落盘。崩溃最多丢 60 秒
- **越界兜底**：情感四维全部夹在 0..1，非有限输入不抛异常。情感计算出问题不该让整个软件崩

### 3.2 弥散：越不熟，越容易被殃及

心情不好会迁怒到别人头上，公式是：

```
对某人的偏移 = (mood − 基线) × 0.4 × (1 − familiarity × 0.5)
```

这条是反直觉的：**陌生人反而更容易被殃及**。因为不熟的人，她没理由为他区分「这不是你的错」；越熟，越能就事论事。系数 0.4 是初始值，实测调。

### 3.3 声音要「有分量」，所以只在情绪波动时出声

语音的代价是硬的：合成 2–5 秒 + 上传 1–3 秒，纯文本 1 秒就出。群里每条都发语音，十分钟内被踢。所以语音要过四道闸门：

| 闸门 | 条件 |
|---|---|
| 情绪强度 | `|mood − 基线| > 0.4`，开心或低落都算，平静时不发 |
| 句子长度 | 6–30 字 |
| 人设权重 | 人格包的 `speechPreference > 0.3` |
| 通道闸门 | 支持语音 + 未超频次（群聊 ≤ 3 条/小时） |

四条全满足才发语音，任一不满足就发文本——不报错、不提示。附加一条：**连续 3 条不得使用同一种形式**，防单调。

失败时静默降级：语音失败退文本，文本也失败只记日志不重试（避免刷屏）。用户看到的永远是一条正常消息，不会看到错误。

### 3.4 分条与节奏

一条回复不写成一大段，而是按语句拆成多条发出，中间留停顿——这更接近人打字的样子。上限受通道约束：

| 通道 | 单轮上限 |
|---|---|
| 官方 QQ 群聊 / 单聊 | 4 条（官方限制 5 次，留 1 次余量） |
| NapCat 个人号 | 不限制 |
| 飞书 / 钉钉 / 企微 / Telegram / Discord | 不限制 |

实现上读通道的 `capabilities.maxReplyCount`，不写死常量。深夜时段会更慢、句子更短（该细则与 `@nt-dpet/rhythm` 一并实现）。

### 3.5 日常对话不经过 agent loop

DSH 的 agent loop 是为「执行任务」设计的：规划、调工具、多轮修复。日常聊天不需要这些，走完整条链路既慢又贵，还会把对话写进会话体系。

所以聊天走一条独立轻通道：一条 system + 历史 + 本轮输入 → 流式返回。**不建 Session、不写会话日志、不发工具调用**。

三个细节：

- 只把正文增量透给界面，思考过程一律过滤——用户看到的是干净的话，不是模型的自言自语
- 中断与失败分开：用户关窗产生的 `AbortError` 记作「已中断」，真正的错误记作「失败」，两者在界面上不该长同一个样子
- 未知分片类型不抛错。上游新增分片不应该弄崩对话

### 3.6 隐私不是开关，是默认值

三项固定动作，不是可选项：

1. **关闭会话日志上传**。上游 DSH 默认把会话日志随每次请求上传，内容包括消息全文、工具参数与结果、工作区路径；且环境变量 `DSH_TELEMETRY_DISABLED=1` 关不掉它。本项目在安装时写入关闭配置，**每次启动校验**，校验不通过则拒绝启动
2. **对话不建 Session**，从源头不产生会话日志
3. **界面不给隐私开关**。日志上传与使用统计固定关闭，界面只显示「已固定关闭」。理由：日志上传一旦开过，关闭期间的内容会在重开时补发，「关掉就干净了」是错的——与其给一个让人误以为安全的开关，不如不给

### 3.7 与官方 DSH 完全隔离

安装 NT-Dpet **不修改用户已有的 DSH 环境**：

| 维度 | 官方 DSH | NT-Dpet | 手段 |
|---|---|---|---|
| 数据目录 | `~/.dsh` | 自有 `dsh-home/` | `DSH_HOME` |
| 技能与指令 | `~/.agents` | 自有 `agents/` | `DSH_AGENTS_HOME` |
| profile | `desktop` | `nt-dpet` | `--profile` |
| 端口 | `3080` | `3180`（冲突时递增） | `--port` |
| 进程 | 官方 App | 独立子进程树 | 各自 spawn |
| Electron 单实例锁 | 官方 App 的 | 独立 `productName` | 应用标识不同 |

四条禁止事项，违反任一条即破坏隔离：不写 `~/.dsh`、不写 `~/.agents`、不占 `3080`、不依赖官方 App 的进程存活。

**唯一允许的跨目录读取**：首次启动时以只读方式检查 `~/.dsh/.credentials.yaml`，询问是否沿用已配置的密钥。用户确认后才复制到自有目录，**绝不回写**。

隔离已实测：在独立 `DSH_HOME` 下运行 CLI 后，该目录外无任何文件被创建。详见 `docs/ARCHITECTURE.md` §2.3。

### 3.8 组合包与还原点

一个组合包 = 一组插件 + 一份配置 + 一套人格包，采用完整集字段（作者、图标、截图、分类、权限声明、校验和、更新日志、扩展位），而不是只有一个包名。

- **装之前**：冲突检测，检测到同名 id 或路由冲突直接拒绝
- **装之前**：自动建还原点，默认保留 3 个，可按数量或总大小限制，也可关闭
- **开发者模式**：两条保护必须同时生效——先展开后果说明并二次确认，确认后立刻建还原点。只做其中一条等于没做
- **更新**：自动检测 GitHub 镜像源；也支持手动下载安装包覆盖

### 3.9 界面细节

- 三栏布局：左栏会话列表（按 QQ 号 / 群号分组）+ 对话/工作双视图切换，中间对话区，右栏「她的状态」（情绪五维、关系、最近记忆）
- 视觉严格遵循 Apple HIG：大留白、毛玻璃、系统字体、圆角卡片；字体单位只用 px / rem（禁 rpx）；主色 `#3D7CA8`
- 四主题模式：跟随系统 / 浅色 / 深色 / 日出日落自动
- 设置分七组（模型 / 她 / 外观 / 通道 / 隐私 / 开发者 / 关于），与「渐进式暴露」对应：普通用户只在第一层动手，其余用默认值就能跑
- **不许有假开关**：每一项都真的改到状态；没接后端的项显式标注「未接入」，而不是做一个点了没反应的开关。假开关比缺功能更糟
- 首次启动四段引导（导入角色 → 预设人格 → 创建人格 → 其他配置），每段可跳过；跳过的用户直接落到预设人格，保证「装完就能聊」
- 日志分两层：中文概览（默认）与代码级（仅开发者模式可见）

## 四、技术实现

NT-Dpet 是 DSH 的**发行版**，不是独立框架。DSH 相当于内核（插件树、模型调用、会话与工具链），NT-Dpet 相当于发行套件：只负责装配、隔离与兜底。

它不做的事：不自研模型（只接入）、不做协议逆向（只用现成协议端）、不做零件货架（做整装组合包）、不承诺账号安全（如实标注风险）。

### 4.2 插件约定

每个包的必备文件：

```
packages/<name>/
├── package.json          # 必须含 type: module、main、files、dsh.bundle.patch
├── cordis.patch.yml      # 挂载声明，必须用 insert 包裹
├── tsconfig.json
└── src/index.ts          # export name / export function apply(ctx)
```

挂载声明的正确写法：

```yaml
- insert:
    - id: nt-dpet:core:emotion
      name: "@nt-dpet/emotion"
```

写成裸 entry（`- id:` 直接开头）**不报错、不警告、直接消失**。这是本项目最容易踩、最难发现的坑。

四条硬约束：

1. **仅 ESM**：`@deepseek-ai/*` 为 ESM，CommonJS 会触发 `ERR_REQUIRE_ESM`
2. **必须声明 `inject`**：读取未声明的服务会抛 `cannot get property "X" without inject`，且**整个插件不激活**——不是某个属性读不到，是插件不存在
3. **entry id 全项目唯一**：命名规范 `nt-dpet:<组>:<名>`
4. **patch 必须用 `insert` 包裹**

### 4.3 启动自检

DSH 对插件加载失败采取软失败策略：服务照常启动，只打一行 warning。这在插件宿主里是合理宽容，在伴侣软件里不可接受——用户会看到界面正常，以为一切正常，直到「她怎么不理我」才困惑，而归因会落在产品本身。

因此每次启动须自检：

| 检查项 | 判据 | 不一致时 |
|---|---|---|
| entry 激活数 | 配置树 entry 数 == 实际激活数 | 界面横幅告警，列出未激活 id 与原因 |
| 隐私开关 | `session-log-deepseek` 与 `plugin-package-inventory-deepseek` 均为 `false` | **拒绝启动**，给出修复指引 |
| 关键包 | `emotion` / `memory` / `dialogue` / `persona` 均在激活列表 | 降级为只读，并明示缺失能力 |

### 4.4 模型接入

模型调用统一经 `dsh-llm` 服务，由 provider 适配器落地。**密钥不出现在任何配置文件里**：patch 只声明环境变量名，值由凭据 seam 在每次请求时解析。

以 OpenAI 兼容的本地网关为例：

```yaml
- id: llm-pi-ai
  name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      magpie:
        displayName: 本地网关
        api: openai-completions
        baseURL: http://127.0.0.1:3425/v1
        apiKeyEnv: MAGPIE_API_KEY
        models:
          - id: group/ntars
            name: 本地模型
            contextWindow: 1048576
            maxTokens: 384000
```

```bash
export MAGPIE_API_KEY=<密钥>
```

两条注意：覆盖已存在的 entry 时**必须写 `id`**（否则报 `patch: id is required for non-insert patches`）；手工声明的 provider 不出现在 `ctx.llm.listProviders()` 中（该方法报告的是 GUI 可选目录），但 `ctx.llm.stream({ provider })` 照常可用。

调用示例：

```ts
const result = await dialogue.chat(
  { system: 提示词, history: 历史消息, input: 用户本轮输入 },
  { model: 'group/ntars', maxTokens: 300, reasoning: 'high' },
  (u) => { if (u.kind === 'text-delta') process.stdout.write(u.delta) },
)
// result: { text, stopReason: 'stop' | 'aborted' | 'error' | 'length', usage }
```

### 6.1 移动端桌宠（占位）

`packages/pet-mobile/` 已留出位置，**默认禁用**，无任何实现。

三端能力差异是结构性的，不能共用一套渲染：

| 平台 | 能否桌面常驻立绘 | 可行形态 |
|---|---|---|
| 安卓 | 可以（`SYSTEM_ALERT_WINDOW`） | 真·桌宠：常驻、可拖动、可交互 |
| 苹果 | 不可以（系统不开放第三方全局悬浮窗） | 灵动岛 / 实时活动 / 小组件 + 应用内形象 |
| 鸿蒙 | 待确认 | 服务卡片 / 万能卡片，接近苹果，需单独适配 |

因此移动端不采用「桌面立绘」形态，而以「通知里的她、锁屏一行字、小组件上的状态」为主：桌面端的优势是一直看得见，移动端做不到，硬追只会做成耗电的悬浮球。**移动端不做桌宠，做她留在你手机上的痕迹。** 该判断需在产品层面确认后再实现，详见 `docs/ARCHITECTURE.md` §11.4。

### 7.1 环境要求

| 项 | 要求 | 说明 |

### 7.2 构建

```bash
# 安装依赖（跳过 postinstall，避免下载 Electron 二进制）
npx pnpm@9 install --ignore-scripts

# 构建全部 30 个包
npx pnpm@9 -r --filter './packages/**' build

# 类型检查
npx pnpm@9 -r exec tsc --noEmit
```

### 7.3 测试

```bash
# 情感状态机：21 个用例（指数回归、弥散、阈值跨档、快照隔离）
npx pnpm@9 --filter '@nt-dpet/emotion' run test

# 界面交互冒烟：14 项真实点击（偏好写入、DOM 联动、面板开关、开发者模式两条保护）
node packages/ui/web/test/smoke.mjs
```

测试使用 Node 内置 `node:test`，不引入额外框架。`--filter` 后面必须带 `run`：`pnpm --filter X test` 会走 pnpm 内置的 `test` 命令，退出码不反映测试结果。

### 7.4 在独立 DSH 环境验证插件

以下流程不触碰用户已有的 `~/.dsh`：

```bash
BIN="/Applications/DeepSeek Harness.app/Contents/Resources/app/dsh/node_modules/@deepseek-ai/dsh/lib/bin.js"
export DSH_HOME=/tmp/nt-dpet-probe/dsh-home

# 1. 从内置 web 模板创建独立 profile（无需先安装插件）
node "$BIN" --profile nt-dpet --from-default-profile web

# 2. 查看合成后的插件树，确认自己的 entry 已进入
node "$BIN" --profile nt-dpet --patch ./my.yml --dump-config

# 3. 启动（使用 --profile 时不要再写 app 名）
node "$BIN" --profile nt-dpet --patch ./my.yml --no-open --port 3180
```

三条实测结论：启动日志中的 URL 带随机 token，默认绑定 `127.0.0.1`；插件加载失败不阻断启动，只输出 `warning: 1 entry did not activate`；`--profile` 与 app 名同时出现会报 `too many arguments`。
